# 浩森設計工作管理系統（PWA）

網址：https://housen-design.github.io/housen-app/
（`app.housenaid.com` 尚未設定：DNS 沒有這筆紀錄、程式庫也沒有 `CNAME` 檔。第一版先用上面的 GitHub Pages 網址，改網域另案處理。）
擁有者：浩森室內設計（林柏元）

## 架構

| 層 | 放在哪 | 內容 |
|---|---|---|
| 前端（PWA） | 這個 GitHub 程式庫 → GitHub Pages | `index.html`（全部畫面）、`config.js`、`sw.js`、`manifest.webmanifest`、`icons/` |
| 後端 API | Google Apps Script 專案「浩森設計工作管理系統_網頁版」（pthz@housenaid.com 的雲端硬碟） | `Code.gs`：登入驗證、權限、讀寫資料 |
| 資料庫 | Google Sheet「浩森設計工作管理系統_資料庫」（共用雲端硬碟／資料庫） | 案件、工程日誌、日誌照片、主管指示、待辦、人員、工種清單… |
| 照片 | 資料庫試算表旁的 `日誌照片_Images` 資料夾 | 與 AppSheet 共用 |

前端只負責畫面，所有讀寫都 POST 到後端 API；後端以表頭名稱對應欄位，改欄位順序不會壞。

## 登入與權限

1. 使用者在登入頁按「使用 Google 登入」，Google 回傳身分憑證。
2. 後端驗證憑證：來源必須是本系統的用戶端 ID、帳號必須是 @housenaid.com、且在「人員」表中「在職」不是 N。
3. 通過後發一組 30 天有效的工作階段憑證（HMAC 簽章，密鑰存在 Apps Script 指令碼屬性 `SESSION_SECRET`）。
4. 要讓某人立刻失去權限：把「人員」表的「在職」改成 N。要讓所有人重新登入：刪除指令碼屬性 `SESSION_SECRET`。

角色：系統角色為 `Boss`、`主管` 可下指示、指派待辦、管理工種；`行政` 可新增案件；其他人可寫日誌、修改任何日誌（系統記錄最後修改人）、管理自己的待辦。

正式版 `Code.gs` 固定 `TEST_MODE = false`：不提供「切換身分」。試玩版（`tests/demo`）只在自己的副本裡打開，不靠正式後端。

## 更新流程

- **改畫面**：改 `index.html` → 推到 GitHub（約 1 分鐘生效）。畫面檔案採「網路優先」，使用者下次開 App 就是新版；App 開著時，系統每 10 分鐘或切回前景會比對網站上的 `index.html`，不同就出現「有新版本，點一下更新」。**不必再手動改版本號**；只有修改 `sw.js` 本身時才要把 `VERSION` 加一。
- **離線或網路很慢（超過 4 秒）**：先用手機裡上次的備份畫面，資料則顯示「無法載入」並可重試。
- **改後端**：在 Apps Script 編輯器改 `Code.gs` → 儲存 → 部署 → 管理部署作業 → 編輯「API」部署 → 版本選「建立新版本」→ 部署。網址不變。
- **新增欄位**：直接在試算表最右邊加欄位，再在 `Code.gs` 用表頭名稱讀寫。

## 設定值（config.js）

- `API_URL`：Apps Script「API」部署的網址（以「我」的身分執行、任何人皆可存取；安全性由登入驗證負責）
- `CLIENT_ID`：Google Cloud 專案的 OAuth 用戶端 ID（內部應用程式，限公司網域），同一個值也要填在 `Code.gs` 的 `CLIENT_ID`

## 網域

目前使用 GitHub Pages 預設網址 `https://housen-design.github.io/housen-app/`，Google 登入的「已授權 JavaScript 來源」也是這個網址。
日後若改用 `app.housenaid.com`，需要：DNS 加 CNAME 指向 `housen-design.github.io`、程式庫加 `CNAME` 檔、GitHub Pages 設定自訂網域，並在 Google Cloud OAuth 用戶端加上新網域。這一版不做。

## 已知限制

- 資料不是即時同步：開啟 App、切回前景、下拉、或每 3 分鐘自動更新。更新失敗時會在上方顯示原因與「重試」，畫面保留上次成功的資料。
- App 關閉時的手機推播尚未做（第二階段，iPhone 需 iOS 16.4 以上且加到主畫面）。
- 未來可用 Capacitor 包成 iOS／Android App，沿用同一份前端。

## 完整功能（分支 feature/full，後端 v4.5）發布步驟
包含：客戶頁（會議、客戶指示與簽名確認）、進度（工序、查驗紀錄、開案 SOP、設計里程碑、延誤提醒）、文件頁（PDF 集中、週報、工程履歷）、
漏填追蹤與無施工登記、結案唯讀與保固報修、統計頁、系統設定（公司設定、範本、工種、經驗回流建議）。
1. Apps Script 貼上 backend/Code.gs → 存檔 → 執行 `checkSchema` 看缺什麼。
2. 執行 `fixSchema`：只會建立缺少的資料表（標題列）和在最右邊補缺少的欄位，不動任何既有資料。再跑一次 `checkSchema` 應顯示「欄位齊全」。
3. 公司設定沒填的項目會用預設值（日誌規則、保固年限等都標「暫定」），可在 App「⚙ 設定」修改。
4. 範本內容目前是示範；Boss 確認後把「範本狀態」改成「正式」，畫面上的「示範」字樣就會拿掉。
5. 建立新版本部署 → 推前端（GitHub Pages）。sw.js 沒變不用改版本號。

## 自動測試（全部假資料，不連任何 Google 服務）

在程式庫根目錄執行一個指令：

```
python3 tests/run_all.py
```

需要 Node.js 18+、Python 3.9+、`pip install playwright && python3 -m playwright install chromium`。
任何一組失敗，結束代碼就不是 0；最後列出每一組的通過數（也存到 `tests/out/summary.json`），截圖在 `tests/out/shots/`。
只跑某幾組：`python3 tests/run_all.py blockers mobiletest`。

| 組 | 內容 |
|---|---|
| 後端 | `cgpt`（外部檢查）、`mergetest`（多人同時編輯）、`blockers`（上線前阻擋項目：切換身分、分享紀錄、同時產 PDF、照片失敗、重送） |
| 畫面 | 各功能的手機操作流程；`mobiletest` 檢查 320×568、390×844、844×390 |
| 試玩版 | 瀏覽器裡跑同一份 `Code.gs` 的試玩網站與 PDF |
| Google 測試環境 | `tests/google-env`：由同一份 `Code.gs` 產生隔離版（只換試算表與雲端硬碟的存取），模擬 Google 驗證隔離 |

## 2026-11-23 上線前修正（後端 v4.9）
- 正式版關閉切換身分（`TEST_MODE = false`）；安裝後可以橫放（manifest 不再鎖直向）。
- 分享／下載紀錄由後端檢查：只接受 share、download；日誌已簽核、PDF 存在且是最新、操作者有分享權限。
- 同一篇日誌同時只會有一個人在產 PDF，另一個人等候並使用同一份；產檔期間有新增指示或回報，完成後維持「待更新」；被取代的 PDF 一律收回，不留孤兒檔。文件 PDF 的紀錄也在鎖內更新。
- 日誌照片先全部上傳成功才寫入試算表；中途失敗會收回已上傳的照片，資料完全不變。同一次送出被重送（例如斷線重按）不會重複新增。
- 這版不需要新增欄位（沿用 v4.8 的欄位）。
